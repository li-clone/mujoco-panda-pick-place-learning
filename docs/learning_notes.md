# Gym、MuJoCo 与仿真学习笔记

## 最小交互闭环

Gymnasium 环境的核心循环是：

```python
observation, info = env.reset(seed=0)
observation, reward, terminated, truncated, info = env.step(action)
```

当前基础环境的动作是七维：

```text
[dx, dy, dz, dRx, dRy, dRz, gripper_delta]
```

前三维是在世界坐标系中的 TCP 位移，接下来三维是旋转增量，最后一维改变夹爪 setpoint。`pixels` 提供 `front` 和 `wrist` 图像；`agent_pos` 包含 7 个关节角、7 个关节速度、夹爪状态和 TCP 三维坐标。

## 从单动作到 Pick-and-Place

学习顺序刻意从单变量开始：先确认环境能 reset/step，再观察 viewer，只改变 X 或 Z，随后读取机器人和物体状态。完整任务不是一个巨大动作，而是一组带收敛条件的 waypoint：移动到方块上方、下探、夹紧、抬升、搬运、放置、松开和撤离。

当前示例直接使用 `environment_state` 或 MuJoCo sensor 的物体真值，因此属于控制和规划练习，不是图像感知策略。真实机器人通常还需要相机标定、目标检测或学习策略、安全限制以及失败恢复。

## 仿真数据与训练位置

仿真可以生成状态、动作、图像、奖励和成功标签，并将数据传到服务器训练。训练程序不必在仿真进程中运行：常见流程是本地或服务器批量采集/生成数据，在 GPU 服务器训练，再将 checkpoint 放回仿真评测。仿真也可以和训练同时运行，例如强化学习并行环境。

本仓库没有采集 LeRobotDataset，也没有训练神经网络；它只验证规则控制、IK 和动力学执行闭环。

## Sim-to-Sim

Sim-to-sim 是把同一策略或控制方案从一个仿真条件迁移到另一个仿真条件，例如：

- 更换物理引擎或机器人模型；
- 改变质量、摩擦、延迟、相机位置和光照；
- 在训练场景之外测试不同初始位置和干扰。

它用于尽早发现控制器依赖某个引擎细节或过拟合固定场景的问题，但两个仿真器都成功仍不能保证真机成功。

## Sim-to-Real

Sim-to-real 是把仿真中开发或训练的方案迁移到真实系统。主要差距包括动力学、摩擦与接触、执行器延迟、关节误差、相机噪声和控制频率。常见手段有域随机化、系统辨识、动作与观测归一化、真机少量微调，以及逐级安全验证。

本项目的 Panda 有 7 个机械臂关节，当前 SO-101 的结构、关节范围、末端几何和控制接口不同。因此这里适合学习方法和工程流程，不能把 Panda 的关节目标、PD 增益或训练数据直接当作 SO-101 真机命令。
